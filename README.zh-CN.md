# NovelSpec 中文指南

> 面向 AI 编程助手的「Spec 驱动」长篇创作框架。

受 [OpenSpec](https://github.com/Fission-AI/OpenSpec)（为 AI 编程设计的 spec 驱动开发框架）启发，NovelSpec 将同样的理念带入故事创作：

> **先搭框架，再动笔写。**

[English version](README.md)

---

## 核心理念

```
→ Spec 优先，不做无准备的下笔
→ 迭代推进，但拒绝无头绪的返工
→ 结构化的约束保证 AI 创作一致性
→ 灵活的框架允许随时调整方向
→ 从短篇习作到史诗巨著皆可胜任
```

## 快速上手

```bash
# 安装
pip install novelspec

# 创建小说项目
novelspec init 我的小说

# 在 AI 助手（Claude Code、Cursor、Windsurf...）中：
# /novel:worldbuild  →  提供你的素材，AI 帮你搭世界观
# /novel:outline 第一部 →  创建章节大纲
# /novel:write        →  开始创作
```

## 读者视角审阅系统（v1.2.0 核心特性）

传统长篇创作中最常见的问题：**作者陷入"上帝视角"而写出不合常理的情节**。写的时候觉得逻辑通顺，但读者一眼就看出不对劲。

NovelSpec 的读者视角审阅系统解决了这个问题——每一章写完、每一部大纲完成，自动从**一个正常读者的角度**审视内容，揪出逻辑漏洞和体验问题。

### 六维审阅体系

| 维度 | 检查什么 | 典型问题示例 |
|------|---------|------------|
| 合理性 🧠 | 人物行为是否符合性格与处境？因果链是否完整？ | 主角明知有埋伏却独自赴约，不符合谨慎人设 |
| 智商在线 🎯 | 有没有"剧情需要强行降智"？决策是否合理？ | 反派在占尽优势时突然废话连篇，给了主角反杀机会 |
| 故事线一致性 📖 | 是否偏离主线？节奏匹配当前阶段吗？ | 铺垫期还未完成就提前进入对峙高潮 |
| 情感共鸣 💔 | 读者真的会被触动吗？还是强行煽情？ | 相识一天的两人生死离别，读者内心毫无波澜 |
| 阅读体验 📄 | 结尾有钩子吗？信息密度适中吗？ | 一整章都是赶路对话，读完后不记得发生了什么 |
| 对话可信度 🗣️ | 这个人在这个场景下会这么说吗？ | 一个粗犷武将突然用文绉绉的词汇对话 |

### 审阅命令

| 命令 | 说明 |
|------|------|
| `/novel:review ch-NNN` | 审阅某一章（读全文 + 交叉检查人物设定） |
| `/novel:review recent N` | 批量审阅最近 N 章（检查连贯性） |
| `/novel:review outline part-XX` | 审阅大纲（**写之前审，避免跑偏**） |
| `/novel:review plot` | 审阅整体剧情框架（结构性问题） |
| `/novel:review all` | 综合审阅（全部已写内容 + 框架） |

### 审阅驱动的工作闭环

```
写第3章 → /novel:review ch-003  →  报告：2个严重问题
        → /novel:revise ch-003  →  修复：调整人物决策
        → /novel:review ch-003  →  确认：问题已解决 ✓
```

审阅报告自动存档在 `chapters/part-XX/ch-NNN/reviews/` 目录中，方便后续复盘。

## 项目目录结构

```
my-novel/
├── novel.yaml                      # 小说元信息（书名、类型、字数规划）
├── world/                          # 世界观框架
│   ├── background.md               # 地理、历史、社会、法则体系
│   ├── timeline.md                 # 世界时间线
│   └── glossary.md                 # 专有名词词典
├── characters/                     # 人物
│   ├── profiles/                   # 人物卡（每人一个文件）
│   ├── relationships.md            # 人物关系网
│   └── speech-patterns.md         # 说话方式特征
├── plot/                           # 剧情
│   ├── overview.md                 # 总纲
│   ├── parts/                      # 各部梗概
│   ├── outlines/                   # 章节大纲
│   ├── foreshadowing.md            # 埋点追踪表
│   └── sub-arcs/                   # 支线设计
├── style/                          # 风格指南
│   ├── narrative-samples.md        # 文风样本（AI 模仿用）
│   ├── forbidden.md                # 禁忌清单
│   └── conventions.md             # 写作约定
├── rules/                          # 创作质量准则
│   └── quality-standards.md        # 九大创作规则
├── prompts/                        # AI 工作指令
│   ├── daily-write.md              # 每日创作指令
│   ├── revise-chapter.md           # 修改章节指令
│   ├── audit-consistency.md        # 一致性审计指令
│   ├── worldbuild.md               # 世界观搭建指令
│   ├── outline.md                  # 大纲创作指令
│   ├── reader-review.md            # ★ 读者视角审阅指令
│   └── propose-framework.md        # 框架变更指令
├── state/                          # 状态跟踪
│   ├── current-status.md           # 当前进度
│   ├── chapter-log.md              # 章节索引
│   └── unresolved-threads.md       # 未解决线索
├── chapters/                       # 章节正文
│   └── part-XX/ch-NNN/
│       ├── summary.md              # 章节概要（350-500字）
│       ├── content.md              # 章节正文（含 front matter）
│       ├── revisions/              # 历史版本存档
│       └── reviews/                # ★ 读者审阅报告存档
├── framework/                      # 框架变更
│   ├── <提案名>/                   # 当前提案
│   └── archive/                    # 已完成提案
└── meta/
    └── changelog.md                # 项目变更日志
```

## Slash 命令速查表

### 搭建阶段

| 命令 | 用途 | 说明 |
|------|------|------|
| `/novel:init` | 初始化项目 | 一键生成完整目录结构 |
| `/novel:worldbuild` | 世界观搭建 | 提供素材后，AI 逐件生成框架，每件确认后继续 |
| `/novel:outline [部名]` | 创建章节大纲 | 按部生成，每章包含核心事件、埋点、视角等 |

### 创作阶段

| 命令 | 用途 | 说明 |
|------|------|------|
| `/novel:write` | 创作下一章 | 自动读取上下文，按大纲写作 |
| `/novel:write --count N` | 批量写 N 章 | 适合有明确大纲时快速推进 |
| `/novel:show ch-NNN` | 阅读章节 | 展示全文 |
| `/novel:show ch-NNN summary` | 只看概述 | 快速了解内容 |
| `/novel:show --recent N` | 最近 N 章概述 | 回顾进度 |

### 审阅与修改阶段

| 命令 | 用途 | 说明 |
|------|------|------|
| `/novel:review ch-NNN` | ★ 读者视角审阅单章 | 六维检查，自动存档 |
| `/novel:review recent N` | ★ 批量审阅 | 检查最近内容连贯性 |
| `/novel:review outline part-XX` | ★ 大纲审阅 | 写之前先审，避免跑偏 |
| `/novel:review plot` | ★ 框架审阅 | 检查整体结构 |
| `/novel:review all` | ★ 综合审阅 | 全局扫描 |
| `/novel:revise ch-NNN 内容` | 修改章节 | 自动保存旧版本到 revisions/ |

### 框架迭代

| 命令 | 用途 | 说明 |
|------|------|------|
| `/novel:propose 内容` | 提出框架变更 | 自动评估影响范围 |
| `/novel:accept 提案名 方案` | 确认变更 | 应用修改 |
| `/novel:archive 提案名` | 归档完成提案 | 清理迭代历史 |

### 维护

| 命令 | 用途 | 说明 |
|------|------|------|
| `/novel:audit` | 一致性审计 | 检查人物/时间线/埋点一致性 |
| `/novel:status` | 查看进度 | 字数、章节数、埋点回收率 |

## 三级存储设计

这是 NovelSpec 支撑长篇创作的核心设计，解决 AI 上下文窗口有限的问题：

```text
┌─────────────────────────────────────────────────────┐
│  L1 — 框架层  (稳定，几乎不变)                        │
│  world/ + characters/ + plot/ + style/               │
│  世界观、人物设定、剧情总纲、风格指南                   │
│  长期存储，每次创作时读取                              │
├─────────────────────────────────────────────────────┤
│  L2 — 状态层  (每日更新，体积小)                      │
│  state/                                              │
│  当前进度、章节索引、未解决线索                         │
│  每次创作必须注入，但因为体积小不会撑爆上下文             │
├─────────────────────────────────────────────────────┤
│  L3 — 产出层  (无限增长，按需引用)                    │
│  chapters/                                           │
│  完整章节正文，只读 summary.md                        │
│  要改某章才读对应的 content.md                        │
└─────────────────────────────────────────────────────┘
```

**核心原则**：AI 每日创作时**只读旧章节的 summary.md**（300-500 字摘要），不读完整的 content.md。这样写到第 100 章时，上下文也不会爆炸。

## 核心理念

1. **先框架，后写作** — 搭建世界观、人物、剧情大纲后再动笔，避免写到一半发现人设矛盾
2. **迭代变更** — 框架变更使用 `propose → accept → archive` 流程，不乱改
3. **写后即审** — 每章写完自动建议读者视角审阅，避免不合常理的情节
4. **伏笔追踪** — foreshadowing.md 追踪所有埋点的埋入和回收，杜绝挖坑不填
5. **一致性审计** — 定期检查人物、时间线、专有名词的一致性
